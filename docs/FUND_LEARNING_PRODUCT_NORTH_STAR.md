# MarketSim 基金学习平台：产品北极星

## 一句话定位

面向零基础用户的基金投资学习网站，通过短课程、真实基金案例、历史回测和模拟训练，帮助用户逐步理解基金，而不是替用户预测涨跌或直接给出买卖指令。

## 核心用户

第一阶段只服务一种人：

> 对基金几乎不了解，或者买过基金但不会分析、不会控制风险的普通学习者。

不为专业交易员、量化研究员、机构投研人员设计第一版。

## 核心学习闭环

```text
学一个概念
→ 看一个真实基金案例
→ 做一道小测验
→ 用历史数据做实验
→ 在模拟账户中练习
→ 写一句复盘
```

所有功能都必须服务这条闭环。

## 第一阶段必须回答的五个问题

用户完成第一阶段后，至少应该能回答：

1. 基金是什么，和股票、存款有什么区别；
2. 股票型、混合型、债券型、指数型、货币型基金有什么区别；
3. 收益率、波动、最大回撤、夏普比率分别说明什么；
4. 为什么不能只看近一年收益选择基金；
5. 为什么要控制仓位、分散风险，并使用模拟而非真实资金练习。

## 产品首页应该做什么

首页不是行情终端，也不是“今日推荐”。首页应该让用户立刻知道下一步学什么。

第一版首页只需要：

- 当前学习进度；
- 推荐的下一节课；
- 三个入口：开始学习、分析一只基金、进入模拟训练；
- 一条固定风险提示；
- 最近一次学习或模拟复盘。

## 现有功能如何复用

### 保留并改造

- 基金搜索：改造成“基金案例查询”；
- 基金详情：改造成“逐项解释这只基金”；
- 历史回测：改造成“历史数据实验室”；
- 模拟交易：改造成“模拟训练场”；
- 自选基金：改造成“学习观察清单”；
- 资讯：只解释资讯可能影响哪些类型的基金，不直接给买卖结论；
- 演示模式：保留，服务课程演示和短视频录制。

### 暂时降级

- 多 Agent：默认关闭，后续作为“多维度规则分析”的实验模块；
- 基金经理风格模型：暂不进入默认学习路径；
- 自动操作建议：不作为第一阶段内容；
- 商业化、会员、支付、正式部署：不开发。

## 文案边界

可以使用：

- 学习；
- 理解；
- 历史回测；
- 模拟训练；
- 风险观察；
- 数据不足；
- 需要关注；
- 历史表现；
- 不构成投资建议。

不要使用：

- 必涨；
- 稳赚；
- 抄底；
- 内部消息；
- 明天买入；
- 一定盈利；
- AI 自动决定买卖；
- AI 预测未来价格。

## 第一阶段范围

### P0：学习主线

- 课程目录；
- 课程详情；
- 每课一个知识点；
- 每课一道或两道小测；
- 本地保存学习进度；
- 首页显示下一课。

### P1：教学工具

- 基金案例分析；
- 历史回测课堂；
- 模拟训练任务；
- 学习复盘记录。

### P2：内容展示

- 竖屏演示；
- 隐私遮挡；
- 固定案例链接；
- 课程卡片适合截图。

### P3：实验功能

- 多维规则分析；
- 学习路线推荐；
- 错题本；
- 学习总结。

### 当前不做

- 真实交易；
- 券商接口；
- 自动下单；
- 收费；
- 会员；
- 支付；
- 实盘跟单；
- 预测未来收益；
- 正式投顾服务。

## 技术原则

1. 不从零重写；
2. 保留现有 FastAPI、登录、基金数据、回测和模拟账户；
3. 新学习功能使用独立模块，避免继续把代码塞进 `ai-backtest.js`；
4. 学习内容先使用静态结构化数据，第一版不需要数据库后台编辑器；
5. 学习进度第一版可以使用 localStorage，稳定后再接用户数据库；
6. 每次只完成一个可验收里程碑；
7. 不允许 Codex自行增加商业化、Agent、云部署或支付任务。

## 成功标准

第一版不是看功能数量，而是看一个零基础用户能否完成以下流程：

```text
打开网站
→ 看到第一课
→ 学完“基金是什么”
→ 完成两道题
→ 查看一只真实基金案例
→ 打开一次历史回测
→ 理解收益和最大回撤不是同一个概念
→ 完成一次模拟训练
→ 留下一条复盘
```

能顺畅完成以上流程，第一阶段才算成功。
